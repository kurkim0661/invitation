# Feature Specification: 모바일 청첩장 (Mobile Wedding Invitation)

**Feature Branch**: `001-mobile-wedding-invitation`  
**Created**: 2026-04-24  
**Status**: Draft  
**Input**: Figma 디자인 기반 모바일 청첩장 구현

## Clarifications

### Session 2026-04-24

- Q: RSVP 폼에서 수집할 정보 범위와 저장 방식은? → A: Google Form으로 리다이렉트. 참석 여부 폼의 상세 구현은 Google Form에서 처리하므로 청첩장에서는 버튼 클릭 시 외부 Google Form URL로 이동만 하면 된다.
- Q: 축의금 계좌 정보 섹션을 포함할 것인가? → A: 포함하지 않음. Figma 디자인 그대로 진행하며, 축의금 계좌 섹션은 현재 범위에서 제외한다.
- Q: "연락하기" 버튼 동작 방식은? → A: 팝업으로 신랑, 신부, 신랑측 혼주, 신부측 혼주 연락처 목록을 표시하고, 각 연락처에 전화 또는 문자 선택이 가능하다.
- Q: 지도 서비스 선택은? → A: 카카오맵 (JavaScript API 임베드 + 길찾기 링크)을 사용한다.
- Q: 갤러리 사진 탐색 방식은? → A: 탭하면 풀스크린 뷰어로 전환, 좌우 스와이프로 사진 탐색 가능.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 청첩장 열람 (Priority: P1)

하객이 모바일 청첩장 링크를 받아 열면, 결혼식 정보(날짜, 시간, 장소, 신랑신부 소개)를 한눈에 확인할 수 있다.

**Why this priority**: 청첩장의 핵심 목적은 결혼식 정보 전달이며, 이것이 없으면 다른 기능이 무의미하다.

**Independent Test**: 모바일 브라우저에서 청첩장 URL에 접속하여 모든 결혼식 정보가 올바르게 표시되는지 확인

**Acceptance Scenarios**:

1. **Given** 하객이 청첩장 링크를 받았을 때, **When** 모바일 브라우저에서 링크를 열면, **Then** "Wedding Day" 헤더, 신랑신부 사진, 인사말, 결혼식 날짜(2026년 7월 11일 토요일 오후 5시), 장소(노블발렌티 삼성)가 표시된다.
2. **Given** 하객이 청첩장을 스크롤하면, **When** 달력 섹션에 도달하면, **Then** 2026년 7월 달력이 표시되고 11일이 강조 표시된다.
3. **Given** 하객이 혼주 정보 섹션을 볼 때, **When** 화면에 표시되면, **Then** 신랑측(김동희ㆍ조진숙의 장남 지환)과 신부측(강대연ㆍ장옥분의 장녀 인화) 정보가 표시된다.

---

### User Story 2 - 오시는 길 확인 (Priority: P1)

하객이 결혼식장 위치와 교통 정보를 확인하여 쉽게 찾아올 수 있다.

**Why this priority**: 하객이 결혼식장을 찾아오는 것이 참석의 전제조건이므로, 정보 전달과 동일한 우선순위를 갖는다.

**Independent Test**: 오시는 길 섹션에서 지도, 주소, 교통편 정보를 확인하고 주소 복사 기능을 테스트

**Acceptance Scenarios**:

1. **Given** 하객이 LOCATION 섹션에 도달하면, **When** 지도가 표시되면, **Then** 노블발렌티 삼성 위치가 지도에 마커로 표시되고, 주소(서울 강남구 봉은사로 637)와 복사(Copy) 버튼이 제공된다.
2. **Given** 하객이 교통편 정보를 확인할 때, **When** 지하철 탭을 보면, **Then** 9호선 봉은사역 4번 출구(도보 4분), 2호선 삼성역 8번 출구(도보 15분) 정보가 표시된다.
3. **Given** 하객이 버스 정보를 확인할 때, **When** 버스 섹션을 보면, **Then** 3417번, 강남01번 버스 및 노블발렌티 정류장 하차 안내가 표시된다.
4. **Given** 하객이 셔틀버스 정보를 확인할 때, **When** 셔틀버스 섹션을 보면, **Then** 봉은사역 5번 출구 우측 50~60m에서 5분 간격 운행 정보가 표시된다.
5. **Given** 하객이 주차 정보를 확인할 때, **When** 주차 섹션을 보면, **Then** 본관(100대, 봉은사로 637, 이중주차 포함 발렛), 별관(200대, 봉은사로 610, 도보 5분 또는 셔틀) 정보가 표시된다.

### User Story 3 - 참석 여부 전달 (Priority: P2)

하객이 결혼식 참석 여부를 전달하여 신랑신부 측에서 하객 수를 파악할 수 있다.

**Why this priority**: 식사 준비 등을 위해 참석 인원 파악이 중요하지만, 정보 전달보다는 후순위이다.

**Independent Test**: 참석 여부 전달하기 버튼을 눌러 참석/불참석을 선택하고 제출하는 플로우 테스트

**Acceptance Scenarios**:

1. **Given** 하객이 참석 의사 전달 섹션에 도달하면, **When** "참석 여부 전달하기" 버튼을 누르면, **Then** 외부 Google Form 페이지로 이동한다.

---

### User Story 4 - 갤러리 감상 (Priority: P2)

하객이 신랑신부의 웨딩 사진 갤러리를 감상할 수 있다.

**Why this priority**: 청첩장의 감성적 요소로 중요하지만, 핵심 정보 전달보다는 후순위이다.

**Independent Test**: GALLERY 섹션에서 사진이 올바르게 표시되고 탐색할 수 있는지 테스트

**Acceptance Scenarios**:

1. **Given** 하객이 GALLERY 섹션에 도달하면, **When** 사진 목록이 표시되면, **Then** 웨딩 사진들이 그리드 형태로 표시된다.
2. **Given** 하객이 갤러리의 사진을 탭하면, **When** 사진이 선택되면, **Then** 풀스크린 뷰어로 전환되어 해당 사진이 표시된다.
3. **Given** 하객이 풀스크린 뷰어에서 사진을 보고 있을 때, **When** 좌우로 스와이프하면, **Then** 이전/다음 사진으로 이동한다.

---

### User Story 5 - 혼주 연락하기 (Priority: P3)

하객이 신랑측 또는 신부측 혼주에게 직접 연락할 수 있다.

**Why this priority**: 일부 하객에게 필요한 부가 기능이다.

**Independent Test**: 연락하기 버튼을 눌러 전화 또는 메시지 연결이 되는지 테스트

**Acceptance Scenarios**:

1. **Given** 하객이 혼주 정보 섹션의 "연락하기" 버튼을 누르면, **When** 팝업이 표시되면, **Then** 신랑, 신부, 신랑측 혼주, 신부측 혼주의 연락처 목록이 표시된다.
2. **Given** 하객이 연락처 팝업에서 특정 인물을 선택하면, **When** 전화 또는 문자 아이콘을 탭하면, **Then** 해당 기능(tel: 또는 sms:)이 실행된다.

---

### Edge Cases

- 갤러리 이미지가 로딩되지 않을 때 대체 표시(placeholder)는 어떻게 하는가?
- 참석 여부는 Google Form에서 처리하므로 중복 제출 관리는 범위 밖이다.
- 주소 복사가 지원되지 않는 브라우저에서는 어떻게 대응하는가?
- 카카오맵 API가 로드되지 않을 때 대체 표시는 어떻게 하는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 모바일 최적화된 단일 페이지 청첩장을 제공해야 한다.
- **FR-002**: 시스템은 "Wedding Day" 헤더, 신랑신부 메인 사진, 인사말 텍스트를 표시해야 한다.
- **FR-003**: 시스템은 결혼식 날짜(2026년 7월 11일 토요일 오후 5시)와 장소(노블발렌티 삼성)를 표시해야 한다.
- **FR-004**: 시스템은 2026년 7월 달력을 표시하고 결혼식 날짜(11일)를 시각적으로 강조해야 한다.
- **FR-005**: 시스템은 양가 혼주 정보(신랑측: 김동희ㆍ조진숙의 장남 지환, 신부측: 강대연ㆍ장옥분의 장녀 인화)를 표시해야 한다.
- **FR-006**: 시스템은 "연락하기" 버튼 클릭 시 팝업으로 신랑, 신부, 신랑측 혼주(김동희ㆍ조진숙), 신부측 혼주(강대연ㆍ장옥분) 연락처 목록을 표시하고, 각 연락처에 대해 전화 또는 문자를 선택할 수 있어야 한다.
- **FR-007**: 시스템은 "참석 여부 전달하기" 버튼 클릭 시 외부 Google Form URL로 리다이렉트해야 한다.
- **FR-008**: 시스템은 웨딩 사진 갤러리를 그리드 형태로 표시하고, 사진 탭 시 풀스크린 뷰어에서 좌우 스와이프로 탐색할 수 있어야 한다.
- **FR-009**: 시스템은 카카오맵 임베드를 통해 결혼식장 위치를 지도에 표시하고, 길찾기 링크를 제공해야 한다.
- **FR-010**: 시스템은 결혼식장 주소(서울 강남구 봉은사로 637)를 표시하고 복사 기능을 제공해야 한다.
- **FR-011**: 시스템은 교통편 정보(지하철, 버스, 셔틀버스, 주차)를 구분하여 표시해야 한다.
- **FR-012**: 시스템은 모바일 기기에서 세로 스크롤로 모든 섹션을 탐색할 수 있어야 한다.

### Key Entities

- **청첩장(Invitation)**: 결혼식의 모든 정보를 담는 최상위 객체. 인사말, 날짜, 장소, 혼주 정보, 갤러리 이미지, 교통 정보를 포함.
- **참석 응답(RSVP)**: 외부 Google Form으로 처리. 청첩장에서는 Google Form URL 링크만 관리.
- **갤러리 이미지(Gallery Image)**: 웨딩 사진. 표시 순서와 이미지 리소스를 포함.
- **교통 정보(Transportation)**: 지하철, 버스, 셔틀버스, 주차 등 유형별 교통편 안내 정보.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 하객이 청첩장 링크를 열고 3초 이내에 메인 콘텐츠(사진, 인사말, 날짜)가 표시된다.
- **SC-002**: "참석 여부 전달하기" 버튼이 1회 탭으로 Google Form 페이지로 이동한다.
- **SC-003**: 주소 복사 기능이 1회 탭으로 완료된다.
- **SC-004**: 모든 섹션이 주요 모바일 브라우저(Safari, Chrome)에서 디자인대로 표시된다.
- **SC-005**: 갤러리 사진이 스크롤 시 지연 없이 부드럽게 로딩된다.

## Assumptions

- 하객은 모바일 기기(스마트폰)에서 주로 접속하며, 안정적인 인터넷 연결 환경이다.
- 청첩장은 정적 콘텐츠 위주이며, 실시간 업데이트가 필요하지 않다.
- 지도 서비스는 카카오맵 JavaScript API를 활용한다.
- 갤러리 이미지는 사전에 준비되어 제공된다.
- 참석 여부는 외부 Google Form으로 처리하며, 청첩장은 해당 URL로 리다이렉트만 한다.
- 디자인은 제공된 Figma 시안을 최대한 충실하게 구현한다.
